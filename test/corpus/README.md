# Test corpus

`typst/` is generated by `tools/typ2tsm.mjs` from the Typst test suite
(https://github.com/typst/typst, Apache-2.0), extracted at case granularity.

Beyond the shared pure-markup subset, the extractor (v2, post M4/M6)
*translates* constructs our engine gained:

- `#set …(…)` statements are stripped — style configuration only; the
  corpus is smoke input, not a rendering comparison
- `<label>` / `@ref` pass through verbatim (same syntax as ours; unresolved
  refs are warnings, not errors)
- term lists `/ Name: desc` → `#term[Name][desc]`
- simple literal `#table(columns: …, align: …, [cell]…)` at line start →
  a `#!table(cols: …)` region (style-only args like `stroke:`/`inset:` are
  dropped; anything with code, spans, or headers is rejected)

Still rejected: any other `#`-call/code (Typst code is not JS), math,
unicode escapes. Current yield: 199 of 1571 cases (12.7%), 133 of them via
translation.

The corpus is smoke/golden input for OUR engine — Typst's pixel references
are not portable across renderers. Run it with:

    node tools/corpus-run.mjs

Every finding here should graduate into a hand-written fixture under
`test/fixtures/` (testing.md §1). Graduates so far: fence edge cases
(`inline/fence-edge.tsm`), the tiny-string-table ops decode bug
(`region/table-tiny.tsm` — SSO dangling-view regression).
