# .tsm author-facing changes

This log lists every change that an author of `.tsm` documents can observe:
new syntax, changed meaning of existing syntax, new diagnostics and changed
defaults. Each entry names the remediation plan step
(`docs/remediation/PLAN.md`) that introduced it and, where needed, how to
migrate an existing document.

Format: `- [step] what changed — migration (if any)`.

## Unreleased (remediation/audit-2026-10)

- [post-P5] A footnote's hover preview is as wide as its text, up to 28em and the page's column; it used to shrink to its narrowest — on a CJK note one character a line.
- [post-P5] A paragraph indent no longer shifts formulas on the plain page (with `par.indent` set, an inline formula's glyphs were drawn one indent to the right of its box, over the following text), and a host page's `text-indent` no longer shifts the typeset lines. On the plain page a display formula's number stands at the right end of the measure, on the formula's line (it stood right after the formula).
- [post-P5] Hosts: `renderTsm(…).settings` keeps `render.idPrefix` (the document wrote the `render` section twice and readers kept the second), so a page that hydrates a second document with its own prefix gets its own ids.
- [P0-04] A `$` that is not closed within its own block (paragraph, heading, cell, link text) is literal text. It no longer takes a closing `$` from a later block, which used to swallow and duplicate the blocks in between.
- [P0-04] An inline `%--` comment that is not closed within its block is literal text, with an error diagnostic, instead of hiding the rest of the document.
- [P0-04] An unbalanced `#let` or `#{` statement reports `statement-unclosed` and is dropped up to the next blank line or the next block start (heading, list item, quote, fence, region, statement). It no longer swallows the rest of the document (`#let`) or pastes broken JavaScript that failed the whole document (`#{`). A `#{` used to recover at the end of its line.
- [P0-04] CRLF line endings read exactly like LF: fence bodies, comments and multi-line formulas no longer carry `\r`, and lines ending in `\r\n` join paragraphs as LF lines do.
- [P0-04] Inside regions, a `|` within `$…$` or a code span no longer splits table cells: `$|x|$` is one formula.
- [P0-05] A runtime error in a block (a ReferenceError in a splice, a throwing `#{…}`) no longer fails the whole document. The block renders as an error block (`script-error`) and the other blocks render normally. A JavaScript syntax error in a statement or splice is isolated to its block (`script-syntax`).
- [P0-05] `#let list = 1` (or any other constructor name) is legal: it shadows the name for your code, while `- item` lists and other markup keep working. Names starting with `__` are reserved (`reserved-name`).
- [P0-05] Repeating `#let x = …` reassigns `x` (it used to fail the whole document). Closures see the latest value.
- [P0-05] `#if`, `#for`, `#while`, `#use`, `#else` and other JavaScript keywords used as a splice head become error blocks (`keyword-unsupported`, `reserved-word`) until the keyword forms land. Before, they failed the whole document.
- [P0-05] Region and fence arguments must be named (`#!table(cols: 3)`, ```` ```js(lineNo: 1) ````). A positional list such as `#!table(3)` is an error block (`header-positional`) instead of failing the document.
- [P0-05] `#let` and `#{…}` inside a list item, quote or region show an error block (`statement-nested-unsupported`) instead of silently disappearing.
- [P0-05] A throwing `$.region` handler becomes an error block (`region-error`), as a fence handler already did.
- [P0-06] Style values are validated. Accepted values:
  - `color`: `#hex`, a color name, `rgb()`/`hsl()`, or `var(--name)`;
  - `font`: a comma-separated family list;
  - `lang`: a BCP-47 tag;
  - `sizePx`: 1–2000.

  Anything else (for example `"red;letter-spacing:5px"`) is dropped with an `ops-arg` warning, so a value can no longer inject CSS. Other numeric arguments are clamped into their range: heading `level` is 1–6, table `cols` is 1–64.
- [P0-07] Content that multiplies when it is placed (`#let b = [#a #a]`, `#let c = [#b #b]`, … forty times over) is cut once the document passes the larger of 262,144 nodes and 64 times its own node count, or 256 levels of nesting. An error (`inst-limit`) stands where it was cut. Before, such a document exhausted memory.
- [P0-08] Text with an absolute size (`#style({sizePx: 22})[…]`) takes its spacing from that size: its CJK gaps, punctuation widths, CJK–Latin spaces, paragraph indent and inline formulas are set in its own em (they were set in the base size's).
- [P0-09] Citations are numbered in reading order, and a footnote's citations count at the footnote's marker. A source cited only in a footnote is numbered where the marker stands, listed in the bibliography and linked; it used to get a later number and be left out. In `@[a, b]` each key resolves on its own: an unknown key shows `??` in its place (`ref-unresolved` names it) and the others still link. A reference whose target is both a label and a bibliography key warns `ref-shadowed` (the label wins).
- [P0-09] Every labelled element is a reference target, and a reference to one without a number is noted (`ref-unnumbered`, info). A label shaped like a generated anchor (`h-2.1`, `fn-3`, `bib-knuth84`) is ignored with `label-reserved`. Of two equal labels only the first keeps its anchor (`label-duplicate`), so no id appears twice on the page. A second `#notes()` places nothing (`flow-already-placed`, info), and a second bibliography's entries carry no anchors.
- [P0-09] Generated text takes the font, language and colour of the place where it stands: a caption's label (图 1), a term's name, the entries of a table of contents or a glossary. They used to be set in the document's base style.
- [P0-09] On the plain page (static export, first paint), footnote links reach their notes (a note of one paragraph lost its anchor), and a labelled display formula shows its number.
- [P0-10] A citation's generated text (`[1]`, `??`) is its own run: copying a passage keeps the punctuation and words next to a citation, and the bracket is no longer copied as prose. A line-final hyphen of a linked word stays inside the link.
- [P0-11] `#bibliography(src)` in Node reads only files below the site root or the document's own folder (a `../../..` path is refused with `bib-load`), and the error points at the `#bibliography` call.
- [P0-11] An image declared with only `w` (or only `h`) keeps that dimension; the other follows the image's aspect ratio (the provider used to overwrite `w`).
- [P0-12] Line breaking follows TeX's rules: the space at a break and at a line start no longer counts in the line's width, the last line may shrink like any other, hyphenation points are discretionary breaks. Some paragraphs break differently (usually fewer widows and loose lines). A word, URL or formula wider than the line is set on a line of its own and overflows it (`overfull-line` warning) instead of crushing the whole paragraph onto one line.
- [P1-02] Footnote markers inside bold or italic text keep their emphasis on the no-JS page (`<sup><strong>1</strong></sup>`).
- [P1-03] Host configuration is one settings document (docs/settings-table.md): `createEngine().typeset(src, el, {settings: {doc: {lang: 'en'}, code: {snapKerning: true}}})`, `renderTsm(src, {settings})`, `export-static --settings site.json`, `tsrc --settings/--set/--profile`. The old named options (`widthPx`, `fontFamily`, `lang`, `punctCompress`, …) remain as sugar; unknown paths and bad values are `setting-unknown` / `setting-type` warnings. Release note: the browser's default body font is now the registry default `"Crimson Text", Georgia, serif` (it was `Georgia, serif` in the shell only), and `export-static` takes the document language from `doc.lang` (English documents export with `lang="en"` and English supplements).
- [P1-04] Fonts are measured per face (family, size, weight, italic), and the typeset root carries the measured font roles (`--tsr-font-body/-cjk/-mono/-mono-cjk`), its language and base size, so the page paints exactly what was measured without host CSS. CJK text inside code is measured in the CJK font (`fonts.monoCjk`, else `fonts.cjk`) as browsers paint it; CJK italics are measured upright, as they are painted (with emphasis marks). New setting `fonts.monoCjk`.
- [P1-06] Inline constructs may cross a line break inside their paragraph whatever separates the lines — a quote's `> `, a list item's indentation, trailing blanks or CRLF: `$a +⏎> b$` in a quote is one formula, `#f[…⏎…]` and `[link⏎text](u)` work across lines. Inside formulas and splice code the line break reads as a bare newline (the next line's indentation is not part of it).
- [P1-06] Code spans follow the run-length rule: ``` ``a`b`` ``` is the code `` a`b ``; a run of N backticks closes only at a run of exactly N, and an unclosed run is literal as a whole. One leading and one trailing space are stripped when both are present (`` ` x ` `` is `x`), so ``` `` `tick` `` ``` shows `` `tick` ``.
- [P1-06] Inside a formula `\$` is a literal dollar (`$a \$ b$`); every other backslash sequence reaches the math parser unchanged.
- [P1-06] Brackets inside formulas, code spans, comments and splice arguments no longer close a footnote, a content argument or link text: `` #strong[code `a]b` here] `` ends after the code span, `[range $[0,1)$](u)` is a link, and `\]` works in `^[…]`, `@[…]`, `#f[…]` and link text alike. A `$` inside link text or a content argument that has no closer before the bracket stays literal (`[price $5](u) and $x$`).
- [P1-06] `@[a, b]` lists ids separated by commas; spaces around each id are ignored.
- [P1-07] A tab advances to the next multiple of 4 columns, so tab-indented list continuations, nested lists and quotes work (a tab used to end the list).
- [P1-07] A list item interrupts a paragraph only when it has content, and a numbered item only when its number is 1: `1984. Then …` on the second line of a paragraph continues the paragraph.
- [P1-07] `-`, `+` and `N.` lists never merge: `+ a` followed by `3. b` makes two lists, the second starting at 3 (the start number used to be dropped). An `N.` that breaks the numbering of its list is reported (`list-number`, info).
- [P1-07] A blank line ends a quote (`> a⏎⏎> b` is two quotes).
- [P1-07] Fences and block comments inside a quote or list item end with their container; fence content inside a list item keeps its own indentation (it used to lose the item's indentation twice).
- [P1-07] A `%--` comment line inside a paragraph no longer splits it. Text after `--%`, `}` or `;` on the same line is kept (it was silently dropped): `#{ let z = 3 } and after: #z.`.
- [P1-07] `#let` and `#{…}` may span lines inside lists, quotes and regions as at the top level (they still report `statement-nested-unsupported` until P2-12), and a broken one inside a container is an error block up to the next blank line instead of the rest of its line only.
- [P1-07] A region closer `#name!` closes the innermost open region of that name; regions opened inside it report `region-unclosed`, as does a region whose quote or list item ends. A closer with no open region of its name is an error block (`region-orphan`) instead of a `#name` splice.
- [P1-08] A construct left open at the end of a line — a formula, a code span, a splice's parentheses, a content argument, an inline `%--` comment — continues onto the following lines of its paragraph, and markup at the start of those lines is text: a formula whose second line starts with `- b` no longer turns into a list, a mid-line `%--` hides the `= …` and `- …` lines up to its `--%`. A formula, code span or call that is still open at a blank line (a comment or block body: at the end of its container) is literal text from its opener, and the following lines are read as usual.
- [P1-08] Content arguments and footnotes take block content: `#callout[` on its own line, then lists, blank lines and paragraphs, closed by a `]` line at the opener's indentation. Bodies are read as blocks, so a body starting with a block marker is that block (`#quote[- x]` is a list); a body that is one paragraph stays inline as before. A footnote `^[…]` may hold several paragraphs and lists.
- [P1-09] ```` ```tsm ```` blocks are highlighted by the engine itself (markers, splice heads, code, formulas, references, labels, emphasis, links, cell bars, fence bodies, comments), with the same tokens the VS Code extension now shows; the extension's outline, folding and completion also come from the engine (region-name completion lists `figure`, `table` and the document's own regions; reference completion includes CJK labels).
- [P1-10] Supplement words come from locale packs chosen by the document language: Japanese documents get 図/表/式 and Traditional Chinese (zh-TW, zh-HK, zh-Hant) 圖/表/式 (both used to get 图); every other language keeps the English words. The `terms.*` settings now override single words on top of the document language (they used to be reset by `doc.lang`).
- [P1-10] A reference to a labelled group that is not a figure (an aside) shows the label text, as the `ref-unnumbered` note says (it showed the figure word with no number).
- [P1-13] An image or raw box in running text (`text #image("x.png", {w: 20, h: 16}) text`) is set on the line's baseline. Before, it was dropped without a word. An inline image whose source is refused or whose size cannot be had is a 1em placeholder.
- [P1-14] The line breaker considers every feasible break, as TeX does; it used to search a window around a first guess. Some paragraphs break differently, usually more evenly, and a paragraph that cannot be set without overfull lines has fewer of them.
- [P1-17] Copying a heading, caption or error block that wraps gives its text as one line; each wrapped line used to copy as a line of its own. A word hyphenated at the end of a line of a sidecar note keeps its hyphen. A float's caption no longer runs past the float's width, and a term defined in a table cell is a link target again.
- [P1-18] A reference to a labelled block lands on its first line whatever that line is. A code block, a rule or a raw box now carries the anchor (links to such blocks led nowhere). When two labelled blocks start on the same line (an aside that opens with a labelled heading), both labels are anchors there.
- [P1-18] Printed sheets keep the ids of headings and labelled equations. Some of them were lost, so references to them went nowhere in print. A heading nested in a region or a list stays with the text after it when printing, as a top-level heading does.
- [P1-24] In a formula a function applies only when `(` follows its name directly. `sqrt(x)` is a root, while `sqrt x` and `sqrt (x)` set the name "sqrt". Without parentheses, `dot` is ⋅, `hat` is ˆ, and other function names (`bar`, `abs`, `vec`) are upright names; a bare one used to spoil the whole formula. — Migration: remove the space in calls such as `sqrt (x)` or `frac (a, b)`.
- [P1-24] Only the faulty part of a formula is lost: it is set as its source in the text font and the rest is laid out. `$x^^2$` shows x followed by `^2`, and the `math-parse` error points at that part; the whole formula used to fall back to its source. A missing or extra argument warns `math-arity` and is marked in place. A formula reports at most 8 problems. In `f'^2` the prime and the 2 form one superscript.
- [P1-25] A formula takes its text's link and colour: in `[range $[0,1)$](u)` the formula is part of the link, and `#style({color: "#a8432a"})[$x^2$]` colours it (formulas ignored both). A display formula takes its block's colour. A character the math font lacks is set and measured in the text font, with one `math-coverage` warning per character. This applies to `$中$` and to `varrho` (ϱ), `varsigma` (ς) and `::=` (⩴), which are now known. Such characters used to be measured as a fixed-size box and painted in whatever font the browser found.
- [P2-01] Splices follow one content rule: a node stays itself, strings and numbers are text, `null`/`undefined`/`false` render nothing (`#x` of `undefined` warns `splice-undefined`), arrays flatten, a function is an error unless it is nullary (`#toc`), other objects show as text with a `splice-object` note.
- [P2-02] Error containment reaches every block: a list item's, quote's or region's paragraph whose code throws becomes an error in its place, and the rest of the list, quote or region renders. A JavaScript syntax error is isolated to the splice or statement that has it, and editing prose no longer re-checks the code. `#let class = 1` (a reserved word) is an error block (`script-syntax`) instead of failing the document. Content arguments go into the call after its own arguments, whatever the argument list looks like: `#f()[c]`, `#f(a,)[c]`, `#f(/* note */)[c]`.
- [P2-02] A splice or statement may `await`: `#let data = await load()`, `#(await f())`.
- [P2-02] Diagnostics of running code point at what runs: `splice-undefined` at the splice, `region-error` at the region (it pointed at the statement that registered the handler).
- [P2-03] Every kind has a constructor, and all constructors share one calling convention: leading arguments bind to the constructor's parameters while they fit (`heading(level, label)`, `list(ordered, start)`, `codeblock(lang, lines)`, `image(src)`, `link(url)`, `raw(html)`, …), then one options object, then the content. `#heading(2)[Title]` and `#list(false)[…]` now bind their content as content (it used to become the label or the start number). New: `group`, `table`, `row`, `cell`, `raw`, `collect`, `styled`, `figure`, `node(kind, attrs, …kids)`. An unknown option is dropped with a `ctor-arg` warning; `width`/`height` mean `w`/`h`, `float` means `side`.
- [P2-03] `$.ctor(name, next => (call, ctx) => content)` overrides a constructor everywhere — explicit calls and markup alike (`$.ctor("strong", …)` changes `*x*` too) — and `next` is the constructor it replaced. A throwing override is an error in place (`ctor-error`).
- [P2-03] `$.region(name, (body, ctx) => content)`: a region handler now receives a Body — `body.blocks()` (the interior as blocks), `body.rows()` (the table reading) — and `ctx` (`ctx.args` are the header's options, `ctx.next(body)` delegates to the previous handler or the default region). It returns the constructor, so `#let callout = $.region("callout", …)` also makes `#callout({…})[…]` work — the same as the region. Migration: a handler `(args, children) => …` becomes `(body, ctx) => …` with `ctx.args` and `body.blocks()`. `$.fence` handlers gain `ctx.next(body)`.
- [P2-04] Diagnostics, editor positions and copy inside content made by code — a splice's result, a region's interior, a constructor's output, a code block's body — point at the source that produced them (they used to point at the start of the document).
- [P3-01] Rules: `#{ $.set(selector, patch) }` styles every later node the selector matches (`$.set('code', {color: '#a8432a'})`, `$.set({kind: 'heading', level: 2}, {size: '1.5em'})`, `$.set({role: 'lead'}, {block: {keepWithNext: true}})`); `#style.where(selector, patch)[…]` does the same for its content. A selector is a kind name or `{kind, role, class, lang, depth, …attributes}`; an unknown kind is an error (`*strong*` is `styled {weight: 700}`, not a kind). Order: engine defaults < host rules < the document's rules < a node's own style < a host rule marked `force`.
- [P3-01] A `$.set` inside a list item or a region body styles the rest of that item or body and ends with it (it was an error); a `$.style.push` there still ends with its statement (`style-in-value`).
- [P3-01] Host settings: `style.rules` is an array of `[selector, patch]` or `{select, patch, force}` — the host's rules, after the engine's defaults; `force: true` wins over a node's own style.
- [P3-01] Kind presentation is default rules, so rules can change it: headings (bold, 1.6/1.35/1.15em, ragged, keep with next), code and code blocks (mono at `code.scale`), captions (centred, unhyphenated, no indent), list and quote insets, footnote markers (`fn-marker`: raised, 0.7em), note bodies (`note-body`: 0.85em), caption labels and term names (bold), comment tokens (class `tok-comment`: italic, hanging at the content), error text (mono). A paragraph of a declared figure-box element is its caption.
- [P3-01] A footnote's body takes the notes list's context, not its site's: a footnote in a heading is no longer bold and large (its own emphasis stays). A list inside a footnote indents by its own (smaller) em.
- [P3-01] The semantic page writes what the document styled; the rules arrive as its stylesheet (`renderTsm` returns `css`, the static exporter inlines it; a mid-document `$.set` is marked with `data-tsr-env`).
- [P5-02] Display formulas and block images follow `par.align` as paragraphs do. `$.set({kind: 'mathblock'}, {par: {align: 'start'}})` sets formulas flush left and `'end'` sets them flush right; `$.set({kind: 'image'}, …)` does the same for images. The default is still centred. Before, the setting was ignored.
- [P5-02] New host settings for code blocks:
  - `code.breakAfter` lists the characters a long code line may wrap after (default: space, tab and `,;)}]>`). Characters are matched by code point, so non-ASCII ones may be listed.
  - `code.commentAware` (on by default) continues a wrapped comment at its text's column.

  That column now also skips non-ASCII lead-in marks (`※ `, `；`), not only ASCII ones like `//` and `#`.
- [P5-02] A code block with line numbers that does not wrap (```` ```js(wrap: false, lineNo: 1) ````) reserves its number gutter. The gutter used to be 0 wide, and printed sheets cut the numbers off.
- [P5-02] Floats:
  - The paragraphs of a framed block (`box: {padding: …}`) keep their right inset after a float. Before, they ran into the frame.
  - Blocks set side by side (`place: {float: "inline"}`) move below a float instead of printing over it.
- [P5-02] In print, a page float taller than a page gets a page of its own and visibly overflows it, with a `page-overflow` warning. Before, it was cut off silently and forced the following text below it. Any printed page whose content runs past its bottom now shows the overflow instead of clipping it.
- [P5-02] A term's name is a label like any other. A term named like a generated anchor (`#term("h-1")[…]`, `fn-1`) warns `label-reserved` and gets no anchor. Of two terms with the same name only the first keeps the anchor (`label-duplicate`). Such terms used to write duplicate ids, and `@h-1` could land on the term instead of the heading.
- [P5-02] A bibliography's entries point at the `#bibliography` call that made them, so the editor jumps there from an entry (they had no source position). Rules and raw blocks also point at their own source; they pointed at the start of the document. `$.bib.format = …` still replaces the default entry format.
- [P5-02] Copy:
  - The line of a display formula ends with a paragraph break, so a blank line separates it from the paragraph after it (there was a single line break).
  - A formula in a table cell copies in its cell's column.
  - On the plain page, a selection inside a footnote marker or a note's backlink copies nothing, and a selection inside a formula copies its source (`$x^2$`), as a selection across them does.
- [P5-01] Formulas can use a host's math fonts beside the embedded Euler. The host declares a font of role `math` with its metrics (`fonts: [{family: 'STIX Two Math', src: '…woff2', role: 'math', metrics: '…tsmf'}]`; `tools/mathc.py --tsmf` compiles them), and the setting `math.fonts: ['stix-two-math', 'euler']` names the chain. Each symbol is set in the first font that has it, and the first font's constants place everything, so `ϱ` and `ς`, which Euler lacks, can come from STIX in an otherwise Euler formula. Formulas without such a declaration are unchanged. New warnings: `math-font-invalid` (a metrics file the engine cannot read), `math-font-unknown` (a name in `math.fonts` that is neither `euler` nor a declared font) and `math-font-mismatch` (a font whose axis or x-height is more than 5% from the primary's: its glyphs sit on the primary's).
- [P5-01] The setting `math.referenceInk` (off by default) lets names, operators and quoted text in a formula take their font's cap height and descender as their extents instead of its full line height, so `lim_(n -> oo)` and `"area"_"max"` carry their scripts as close as `x_i` does.
- [P4-08] Justification is one model for Latin and CJK text: a CJK gap stretches and shrinks k (0.6) times as much as a word space, both in choosing the breaks and in setting the line, so CJK paragraphs break a little differently (fewer loose lines and short last lines; lines may tighten slightly more). The host setting `doc.cjkGlue` is retired. No space is added between a Chinese character and Latin punctuation any more (`圖/表` sets solid; spacing stays between a character and a Latin letter or digit), and a line never starts with `/`, `,`, `)` or a quote that follows a Chinese character.
- [P4-07] A space before a footnote no longer moves after it: `word ^[note]. end` reads "word¹. end" (it used to read "word¹ . end"); the mark hugs its word, and after Chinese punctuation it sits right after the glyph (`。¹`), the punctuation's spacing after the mark. `#attach('prev')[…]`, `#attach('next')[…]` and `#attach('both')[…]` attach any inline content the same way: no space, spacing or line break on that side.
- [P4-06] Hyphenation follows the text's language: `#style({lang: 'de'})[Übersetzung]` hyphenates with German patterns (Über-set-zung), which the host provides (the browser runtime ships the patterns of some 80 languages); English patterns no longer cut words with letters they do not know. Without patterns for a language its words hyphenate only at soft hyphens (a warning says so); en-GB and other English variants fall back to the American patterns.
- [P4-06] A line may break after the hyphen of a hyphenated word (`well-|known`), and compounds hyphenate in their parts. Very short pieces stay together: `e-mail`, `X-ray`.
- [P4-06] Long URLs, paths and identifiers break by the Chicago Manual's rule: after `//` and colons, before `/ . _ - ? # %` and `@`, around `=` and `&` — never inside `https://`. This now applies in headings, captions and inline code too (a long URL in a heading used to run off the line). `#style({text: {overflowWrap: 'anywhere'}})[…]` lets a long token break between any characters; `'normal'` keeps it whole.
- [P4-05] Plain-text break controls work:
  - A no-break space (U+00A0) keeps `10 km` together but stretches like a space.
  - A zero-width space (U+200B) allows a break.
  - A word joiner (U+2060) forbids one.
  - A soft hyphen (U+00AD) marks where a word may hyphenate.
- [P4-05] Japanese and Korean text: small kana, ー, 々, ・ and 〜 never begin a line, and 〖〗｟｠ are brackets. Hangul breaks between syllables, keeps its spaces, and gets no CJK–Latin spacing; line breaks in Korean source read as spaces.
- [P4-04] New text properties for `#style({text: {…}})` and `$.set` rules. `wrap: 'nowrap'` keeps a phrase on one line. `autospace: 'none'` drops the CJK–Latin spacing at its edges. `hyphens: 'none' | 'manual' | 'auto'` and `overflowWrap: 'normal' | 'separators' | 'anywhere'` override a block's own hyphenation and long-token rules. `space: 'pre'` keeps a text's spaces as written.
- [P4-04] A run of spaces inside spliced text (`#("a   b")`) reads as one space, as the browser shows it. It used to be budgeted as several spaces, which left justified lines short.
- [P4-03] Every word of the typeset page points at its own source. The editor's jump from the preview lands on the word clicked, also after escapes, joined lines and hyphenated words. A line's position is its first word's. Before, a run pointed at the start of its text node, and a line at the earliest source of anything on it.
- [P4-02] Markup no longer changes spacing or breaking. CJK–Latin spacing now goes at every script edge, including next to emphasis, links, references and inline code: `中文*English*中文`, `中文[链接](…)`, `中文`code`中文`, and `(1)` before CJK text. Each such edge is also a line-break opportunity. A footnote's reference digit still hugs the text on both sides.
- [P4-02] A line break in the source joins two CJK lines without a space across markup too: `这是*强调*⏎中文` and `他说“好”⏎然后` read as written (they used to gain a space).
- [P4-02] Curly quotes are set as pairs. `他说：“Hello”之后` and `，“*强调*”。` set both quotes as Chinese punctuation; they used to split one Latin and one Chinese. A quote set off by spaces from Chinese text stays Latin, and `#style({lang: 'en'})[“OK”]` still forces Latin.
- [P4-02] A line never begins with the punctuation after a formula: `($a=b$)`, `$x$,` and `$f$th` keep the `)`, `,` and `th` with the formula. Nor does a CJK closing mark begin a line after a typed space (`！ ？`).
- [P4-01] Text next to a link, a reference or a colour change in the same font is measured with the kerning the browser applies across that edge, such as between a link's last letter and the comma after it. Justified lines that hold links now end exactly at the margin.
- [P3-35] Front matter: with the host option `source.frontMatter` (the VS Code extension sets it; a site generator passes it in its settings), a `---` line at the very start of a document through the next `---` (or `...`) line is the site generator's metadata — skipped, a comment. Without it, those lines are markup as before (a rule, a paragraph).
- [P3-35] Tools: `runtime/src/shared/tsm-print.mjs` prints a parsed document back to `.tsm` and escapes any text for a place in a document (`escapeTsm`); the converters (`tools/convert/`) decode every HTML entity, escape text with it — no more stray emphasis from `x_i` or broken footnotes — and write description lists; `tools/translate-tsm.mjs` protects code, formulas, references, splices, URLs and footnote markers by the engine's own parse and checks a translation's structure against the original.
- [P3-34] Description lists: `/ Term: description` lines, one after another, are a description list. The term (anything up to the first `:` followed by a blank or the end of the line; markup allowed, `\:` for a colon in it) is set in bold at the start of its description, and the description's lines after the first hang 2em in; a second paragraph of the description is indented to the same 2em (indent its source lines past `/ `). The semantic page writes `<dl>`, `<dt>`, `<dd>`. Scripts build the same with `terms(item({term: "Term"})[description])` — every kind's constructor now takes its slots as options (`item({term})`, `para({tag})`). Before, `/ Term: description` was a paragraph that began with a slash. Also: blanks between the parts of a list, a table, a row or an equations block (`#list[#item[a] #item[b]]`) are no longer reported as text the list cannot hold.
- [P3-33] Markup stays out of ordinary words. `*` and `_` between two ASCII letters or digits are text: `snake_case_name`, `2*3*4` and `NEED_IMAGES` no longer start emphasis (CJK neighbours are unaffected: `中*强调*文` still pairs). `@` and a bare `#name` right after a letter or digit are text: `user@host.org`, `word#todo`, `C#` (a call or content argument after it stays a splice: `H#strong[2]O`). **Behavior change:** emphasis inside a word — `d_upper A_` — is now literal; write `d#em[upper A]`.
- [P3-33] A bare `http://` or `https://` URL is a link to itself, verbatim: `_` and `*` inside it are part of the URL (they used to make italics in the middle of the address). It ends at a blank, a non-ASCII character or one of `` < > " ` | \ $ ``; trailing punctuation (`. , : ; ! ? ' * _ ~`) and an unbalanced `)` or `]` stay outside. Inside a link's own text a URL is text. A URL followed directly by CJK text ends before it (`见https://a.com/x。`); for an address with non-ASCII characters write `[text](url)`. To keep a URL as plain text, escape its colon: `https\://…`. **Migration:** do not escape characters inside a URL (`y\#frag` now ends the link at the backslash; write `y#frag`).
- [P3-33] A backslash escapes ASCII punctuation only. Before the end of a line it is a hard line break (the line ends there, unjustified; new: `#linebreak` does the same); before anything else it stays a backslash (`C:\temp`, `\a`). **Behavior change:** `\x` before a letter, a digit, a blank or a non-ASCII character used to drop the backslash silently; it now shows. **Migration:** remove such backslashes (TeX leftovers like `i.e.\ ` or `\TeX`), or write `\\` for a backslash. `\` at the end of a line used to print a backslash.
- [P3-33] Text next to an unclosed marker is one text (`请注意*以下事项`): the CJK–Latin spacing rules see the `*` between Han characters, which now gets the narrow boundary space a Latin character gets.
- [P3-31] `#use("./lib.mjs")` uses a JavaScript module: its default export runs as `default($, std)` (register fences, regions, math functions, element declarations…), its `fences` and `regions` exports register by name, its `providers` answer this document's code tokens or image sizes. It renders nothing; what it registers applies from that line on. The path is relative to the document (in a browser, the page or the host's `baseUrl`); a changed module is loaded again, an unchanged one is reused, so a module must not keep state between runs (the recorder and the dev-mode `checkExecution` policy run a document twice and say `exec-nondeterministic` when the results differ). A module that cannot be loaded or throws is a `use-module` warning, and the document renders without it. `#use` used to be an error block (`keyword-unsupported`). Also: a paragraph whose only content is statements that render nothing (a `#use` line) is gone, not an empty paragraph.
- [P3-31] References cross files of one project: `@sec-two` in one chapter finds a label of another chapter when the host gives it the other chapters' label manifests (the project driver does: see `tools/tsm-project.mjs`). It is numbered as this document numbers that kind of element (its own words and patterns), with the other chapter's start applied ("§2.1"), and links to that chapter's page. A local label of the same name wins (an info `ref-shadowed`). `#{ $.labels.import("ch1.labels.json") }` imports one manifest from a document itself; `node tools/tsm-project.mjs build` renders a whole book (`tsm.project.json`), numbering continued across files.
- [P3-30] A document's language is detected from its text when the host does not set one (`doc.lang` defaults to `auto`): an English document gets "Figure 1" and "Eq. (1)", a Japanese one 図 1, a Traditional Chinese one 圖 1, a Korean one 그림 1, a Simplified Chinese one 图 1 as before; the page's `lang` follows. A document says its own language with `#{ $.doc({lang: "en"}) }` (it wins over the host's) and its own words with `#{ $.locale("en", {terms: {figure: "Fig. "}}) }`. **Behavior change:** hosts that set no language used to get zh-CN for every document (图/表/式). Curly quotes, the em dash and the ellipsis follow a run's own language when it has one: `#style({lang: "en"})[“OK”]` sets Western quotes beside Chinese text, `#style({lang: "zh"})[“OK”]` full-width ones. A formula with an unclosed bracket (`$($`) no longer breaks the page in the browser.
- [P3-29] Display lines one after the other (two or more lines `$ … $` with nothing else between them) form one block of equations: their rows align at `&` (`$ f(x) &= … $` / `$ &= … $`), and each labelled row gets its own number. Inside one display formula, a `\` at the end of a line starts a new row (Typst's line break); the formula keeps one number, on its last row. Scripts build the same block with `math.equations([rows])`. Before, consecutive display lines were separate, unaligned displays, and a line-final `\` was a literal backslash.
- [P3-29] New in formulas: matrices `mat(1, 2; 3, 4)` (also `pmat`, `bmat`, `Bmat`, `vmat`, `Vmat`), `cases(x & "if" x >= 0; -x & "otherwise")` and `aligned(f(x) &= (x+1)^2; &= x^2 + 1)` — `;` between rows, `&` between aligned cells (and `,` in matrices); `$.math.fn` takes rows parameters (`["r: rows"]`, `["r: cells"]`). `overbrace(a + b, n)`, `underbrace`, `overbracket`, `underbracket`, `overparen`, `underparen`; `attach(x, t: a, b: i, tl: 1, br: 2)` with named arguments (`name: value`, for a function's own parameter names); `big(()`, `Big`, `bigg`, `Bigg`; `phantom`, `hphantom`, `vphantom`, `smash`. Accents over a base of several glyphs widen: `hat(x y z)` is a wide hat, `vec(A B)` a long arrow (one letter keeps its accent). The converters (tex2tsm, pbr2tsm) now write these constructs instead of flattening matrices, alignments and braces. **Behavior change:** `&` in a formula is an alignment point, never an ampersand (quote it: `"&"`).
- [P3-28] `raw(html, {measure: "host"})` is measured: a block box takes the height its markup has at the measure's width (a chart, an embed, wrapping text), measured again after a resize; an `<svg>` with a `viewBox` (or a px `height`) is sized by the engine itself. An inline box needs its width, `{w: 120, measure: "host"}`, and sits on its measured baseline. It used to keep its declared height (an info diagnostic) and clip what did not fit. A box the browser cannot measure keeps its declared height (`box-measure` warning). A fence handler's `ctx.raw(html, options)` now takes every `raw` option (`measure`, `minWidth`, `w`/`h`, …), not only `width` and `height`. Raw content, block or inline, is laid out with the document's font, normal line-height and wrapping (inline raw text used to inherit the line's zero line-height and no wrapping).
- [P3-27] The no-JS page sets formulas as the typeset page does (the same boxes, glyphs and number placement, the math font shipped by `export-static`) instead of their source in `<code>`; the host setting `render.math: "source"` restores the source. Formulas on both pages carry `role="math"` and their source as `aria-label`, so a screen reader reads `a^2 + b^2 = c^2` rather than glyph by glyph (`a11y.mathLabel: false` turns it off). New opt-in setting `a11y.textLayer`: the typeset lines are hidden from assistive technology and a visually hidden copy of each block's content text (what copying it gives: no hyphens, list markers or equation numbers) stands beside them.
- [P3-26] An equation number is set by the layout: on the formula's baseline at the end of the line (it was centred on the row by CSS), and on a line of its own below a formula too wide to leave room for it (it overlapped the formula). Copy still leaves it out, on the typeset and on the plain page.
- [P3-25] An inline formula breaks inside a sum or an integral like anywhere else (it could not: `sum_i a_i + b_i + c_i = x` overflowed the line), after a scripted relation (`=^"def"`) and after the operator that follows a scripted group (`(a+b)^2 - c`). A minus right after such a break is a sign, not an operator. `x^ab` sets ab as the exponent (it was x^a b), `a/bc` is a over bc. Host settings: `math.breakAfter` and `math.breakBefore` (`{"rel": 0.8, "bin": 0.95}`, `{"rel": 0.85}`: a penalty per atom class, a class not given never breaks) replace `break.mathRelAfter`, `break.mathRelBefore` and `break.mathBinAfter`.
- [P3-24] **Behavior change (D-M01):** only parentheses disappear around a script, fraction or call operand. `x^{a b}` now shows its braces and `x^[a]` its brackets (they used to vanish like parentheses); write `x^(a b)` for an exponent without brackets, or `class(ord, …)` for an atom. — Migration: change `^{…}` / `_{…}` that should not show braces to `^(…)` / `_(…)`.
- [P3-24] Typed symbols behave as their names: `∑_(i=1)^n` has limits like `sum`, a typed `≤` ends a sum's body, and `⟨ … ⟩`, `⌊ … ⌋`, `langle … rangle` are delimiters that stretch. A bar alone in a group is its middle: `{x | x > 0}` and `P(A | B)` stretch the bar and space it as a relation (`|x|` and `||v||` are unchanged).
- [P3-24] Negation is one rule: a `!` touching a symbol negates it (`!=`, `!in`, `!exists`, `!|`, `!||`, and now any relation the Unicode data negates, `!models` ⊭). A relation that has no negation is an error where it stands (`!<<`). `n!` and `n! = 1` are factorials. `_|_` is gone: write `perp` (or `bot`) for ⊥. — Migration: replace `_|_` with `perp`.
- [P3-24] New in formulas: the alphabets `bb(R)`, `cal(A)`, `frak(g)`, `bold(v)`, `italic(h)`, `sans(x)`, `mono(x)` (letters and digits; `NN`, `RR` remain); the spaces `thin`, `med`, `thick`, `quad`, `wide`; `display(…)`, `inline(…)`, `script(…)`, `sscript(…)` for a part's style; `limits(…)` and `scripts(…)` for where an operator's scripts go (`limits(lim)_(x -> 0)` inline); `class(rel, …)` for the spacing of anything. A word the formula does not know (`Equiv`) is still set upright as an operator name, and now says so (info `math-implicit-name`): declare it with `$.math.op` or quote it.
- [P3-24] `tools/convert/tex2tsm.mjs` converts `\mathbb`/`\mathcal`/`\mathfrak`/`\mathbf`/`\mathsf`/`\mathtt` to the alphabets, `\operatorname{X}` to `class(op, "X")`, `\quad`/`\,` to the spaces, every symbol through the engine's own map (`\langle` was converted to a name the engine did not have), and lists the math macros it has no symbol for. `pbr2tsm` writes bold, script and fraktur MathSpeak letters with the alphabets.
- [P3-23] The plain page (static export, first paint) shows constructs as their elements: a defined term is a `<dl><dt>…</dt><dd>…</dd></dl>`, a table of contents, list of figures/tables or index a `<nav>`, the glossary, notes and bibliography a `<section>` (with their ARIA roles). A figure's caption is one `<figcaption>`: a caption of several paragraphs keeps them apart, and a block inside the figure stays out of it. A code block's sidecar notes follow their lines inside the code, behind the fence's marker (copy still takes only the code). Runs keep their weight (600, 300) and relative size (`size: '0.8em'`) as on the typeset page; a rule on a role reaches the plain page's groups (`[data-role]`), a rule on a class its runs (comments are italic there too).
- [P3-23] A document or a host chooses how a class shows: `$.element('theorem', {…, html: {element: 'section', aria: 'note', typeset: {frame: true, dataRole: true}}})`, `$.element('key', {html: {element: 'kbd', inline: true}})` for `#strong({role: 'key'})[Ctrl]`, or the host setting `semantics.html` (`{"quote": {"element": "aside"}}`). Elements and ARIA roles come from an allowlist (`script`, `iframe`, `img` and the like are refused). On the typeset page a group's block carries `data-role="<role>"` (theme hook), and a class declaring `typeset.frame` gets a `.tsr-frame[data-role]` box the theme draws. `html: 'figure'` on a class now reads like the figure row; a class whose paragraphs are not its caption part no longer becomes a `<figcaption>`.
- [P3-22] Literate fragments are opt-in. ```` ```cpp-literate ```` is C++ with `<<fragment name>>` references and `<<name>>=` / `<<name>>+=` headers set as labels (a CJK name works). Plain ```` ```cpp ```` no longer does this, so `(1 << n) >> 2` stays two shifts. Any language can take the overlay: ```` ```py(overlays: ["noweb"]) ````, or a rule `$.set({kind: 'codeblock', lang: 'py'}, {codeblock: {overlays: 'noweb'}})`; `overlays: []` switches it off (also for `cpp-literate`). An overlay name the engine does not know is reported (`code-overlay`). — Migration: a literate C++ block becomes ```` ```cpp-literate ```` (`tools/convert/pbr2tsm.mjs` writes it so).
- [P3-22] In a rule's selector for code blocks, `lang` is the code's language: `$.set({kind: 'codeblock', lang: 'cpp'}, …)` styles C++ blocks. It used to mean the text's language, which `textLang` still selects. `c` fences are highlighted as C++, and font features configured for a language (`code.fontFeaturesByLang`) apply to its every fence tag (`c++`, `cc`, `c`, `cpp-literate` for `cpp`); a tag configured itself keeps its own.
- [P3-21] `$.load(src, {as: 'text' | 'json' | 'bytes'})` reads a document resource from a script (a promise); handlers' `ctx.load` takes the same `{as}`. A path resolves against the document: its page in the browser, its folder in Node, where it must stay below the document root. A URL is loaded only over http(s). A failed or refused load rejects with its reason ("resource outside the document root"). `#bibliography(src)` reads through the same loader, with the same cache.
- [P3-21] Static export (`tools/export-static.mjs`): `<title>` is the document's first heading unless `--title` is given (it was the file name), and `<html lang>` is the language the engine typeset with (`docinfo`). The images, bibliographies and loaded files beside the post are copied into the export at the same relative paths. `renderTsm` returns `{html, css, diagnostics, ok, manifest, settings, docinfo}`: `manifest` lists every resource the document referenced or loaded, with its status. Its diagnostics no longer carry `rule-no-css` warnings about the engine's own default rules, only about the host's and the document's.
- [P3-20] A link or reference URL must be a relative reference, `http(s):` or `mailto:`. Any other scheme (`javascript:`, `data:`, `vbscript:`, a scheme spelled with tabs or spaces) is dropped with an `ops-arg` warning, and the link text stays as plain text. Before, the URL became a live `href` on the typeset page, the plain page and the static export. A role's `html` (`$.element` and host `semantics.*` patches) must be a phrasing element (`sup`, `sub`, `strong`, `em`, `mark`, `span`, `code`, `kbd`, …); any other element name refuses the declaration. — Migration: write a `data:` or script link as text, or host it at an `http(s)` URL.
- [P3-19] Text keeps its place in its line whatever `line-height` the surrounding page sets. The engine now pins every line's baseline, so embedding a document in a site with its own `line-height` no longer shifts the text against rules, images and code.
- [P3-18] A `class` on any construct reaches the page as `tsr-c-<name>` on its text, both typeset and on the plain page. A stylesheet can style `#strong({class: 'warn'})[…]` with `.tsr-c-warn { … }`. Code token colours are classes (`.tsr-c-tok-keyword`, …) set by the default theme (`theme.css`, exported as `THEME_CSS`), so a theme can recolour code without touching the engine. The engine's own stylesheet (`TSR_CSS`) no longer holds colours.
- [P3-17] A block placed inside a paragraph splits the paragraph around it: the text before, the block, then the rest of the paragraph without a first-line indent or extra space. Blocks include a `#rule()`, a `#toc()` and a display formula `$ … $`. A display formula in the middle of a paragraph is now set apart and keeps its label (it used to be set inline and lose the label). A block inside a heading or a link is an error.
- [P3-16] The page's vertical spacing follows the layout exactly: paragraphs are 19.203px apart, not 19.2px, and a trailing float no longer overlaps what comes after the document. Error text is styled as an error (`.tsr-err`, red by default) and shows its message on hover. Printed code listings keep their line numbers.
- [P3-15] Any block can float:
  - `style: {place: {float: "right", width: "45%"}}` on a figure holding a table, an aside or a code block floats it, and the text wraps beside it. Without a width it takes its content's width.
  - `place: {float: "inline", width: "45%"}` sets blocks side by side (subfigures); they wrap like words when the page is narrow.
  - `place: {float: "top" | "bottom" | "page"}` makes a page float. It stays in place on screen; in print it goes to the top or the foot of its page, or onto a page of floats after it.
- [P3-14] Layout traits, set by rules or a block's own style:
  - `$.set({role: 'theorem'}, {box: {padding: '0.4em 0.8em', border: '0 0 0 2px', borderColor: '#2f5d8a', background: '#f4f7fb'}, keep: 'together', space: {before: '1.5em', after: '1.5em'}})` frames a theorem, sets it apart and keeps it on one printed page.
  - `keep: 'with-next'` keeps a block with the block after it when printing.
  - `par: {hang: '2em'}` gives a hanging indent (reference lists).
  - `break: {before: 'page'}` and `#pagebreak()` start a new printed page.
  - `media: 'screen' | 'paged'` shows a block only on screen or only in print.
  - `beside: 'shrink'` lets a code block or table sit beside a float instead of moving below it.
  - `breaker: {tolerance, emergencyStretch}` tunes line breaking.

  A region takes these as `style: {…}`, for example `#!aside(style: {break: {before: "page"}})`.
- [P3-14] Tables:
  - `cols` may list columns, `[{width: "auto", align: "l"}, {width: "1fr"}, {width: "6em", align: "r"}]`. A width is `auto`, `min-content`, `max-content`, a number of fr, a length or a percent.
  - `rules: "booktabs" | "grid" | "none"`.
  - `header: n` marks the header rows, which repeat on each printed page.
  - Cells take `#cell({colspan, rowspan, align, valign})[…]`, also inside a pipe row.
  - A table too wide for the page scrolls sideways on screen and warns `table-overflow`.
  - A row with more cells than columns now widens the table and warns `table-cells`; the extra cells used to be silently dropped.
  - `raw(html, {minWidth: "8em"})` sets the least width a raw box takes in a content-fitted column.
- [P3-13] New collections and flows. All of these are declarations (docs/semantics-design.md §9); existing documents read as before.
  - Lists:
    - `#lof()` and `#lot()` list the figures and tables with their captions.
    - `$.collector(name, {select: ['theorem'], head, entry})` makes a list of your own classes.
    - `$.collector(name, {like: 'notes', …})` starts from a built-in.
  - Index: `#entry({role: "index", key: "monad", sortKey: "monad"})[monad]` marks an index entry where it stands, and `#index()` lists the keys in sort-key order with links to every place.
  - Notes:
    - Named notes: `#note({label: "src"})[…]`, then `#ref("src", {form: "marker"})` for each further marker. The single note links back to every marker (`↩ a b c`).
    - Notes per chapter: `$.counter('footnote', {within: {counter: 'heading', depth: 1, prefix: false}})` restarts the numbers without prefixing them. `$.element('footnote', {flow: {placement: 'section-end'}})` puts each chapter's notes at its end.
    - A collector with `scope: 'section'` takes only its section's items.
    - Print: `$.element('footnote', {flow: {placement: 'deferred'}})` sets notes at the foot of the page of their marker, below a rule; the screen still shows them at the end.
  - Citations:
    - `#!refsection … #refsection!` numbers its citations afresh.
    - A bibliography inside a refsection lists that section's citations.
  - Counters and headings:
    - Counter systems take `mode: 'additive'` with `weights` (roman numerals).
    - Heading classes declared per level (part, chapter) nest in the table of contents.
- [P3-12] Printing: a code block's last line no longer starts a page alone (its lines keep two together at a page cut, like a paragraph's); a table may break between its rows; a block taller than a page shows whole instead of being cut off. The page is set by `page.width`, `page.height` and `page.margin` (the defaults: A4 with 64px margins) — print options still override them. Pagination warns when it has to break a keep (`keep-violated`) or a block does not fit a page (`page-overflow`).
- [P3-11] A code block with `wrap: false` keeps snap-kerning (it was silently off). A code block with sidecar notes is laid out as a two-column table of its lines — the same output.
- [P3-10] A table cell holding blocks lays them out: a list keeps its markers and items, two paragraphs keep their gap, a code block keeps its lines (`#table({cols: 2}, row(cell("Steps"), cell(list(false, item("one"), item("two")))))`); they used to run together on one line. A cell of text is unchanged.
- [P3-09] Ragged text (headings, start/end-aligned and centred paragraphs, table cells) now breaks knowing its lines will not be stretched: fewer hyphens and fewer tight lines. Captions are justified and hyphenated, and a caption that fits on one line is centred (a long caption used to be centred line by line); float captions too. New block property `par.singleLine: "center"` centres a paragraph only when it is one line (`$.set({role: "note"}, {par: {singleLine: "center"}})`).
- [P3-08] Text beside floats is shaped line by line:
  - Each line is narrowed by the floats its height meets, so no line overlaps a float.
  - Two floats stacked on one side narrow the text only as far as each reaches. Before, the text was narrowed to the wider one.
  - A left and a right float can face each other with text between them.
  - A paragraph that would get a column narrower than `layout.minWrapWidth` moves below the floats instead. This is a new host setting, 8em by default.
  - A float adds no paragraph gap after itself.
  - In a list, the text after a float starts level with the float's top and keeps room for its marker.
- [P3-07] Copy takes what you see: references and citations now copy as their text (`§1`, `[1]`; they were dropped), while footnote markers, the notes' `↩`, list markers, line numbers, equation numbers and error text are left out. A table copies as tab-separated rows (an empty cell keeps its column; a word hyphenated in a cell rejoins), a blank line inside a code block survives, a code block with sidecar notes copies only the code (select inside the notes to copy them), paragraphs inside a quote or region are separated by a blank line, and copying from printed sheets keeps paragraph breaks. `copy: "text" | "omit" | "replace:…"` and `syn` on any constructor say what copy takes of your own content (`#ref({copy: "omit"}, …)`). Hosts: lines carry `data-track` (`cell`, `sidecar`, `caption`) instead of `data-cell`, and `data-join` gains `tab`, `row` and `para`.
- [P3-06] Hovering a footnote marker — or an `@fn-1` reference — shows the note as written, with its emphasis and code (it was plain text read off the typeset lines: a word hyphenated at a line end showed its hyphen, Chinese text got spaces where the lines broke). `$.element(name, {preview: "block"})` gives a class the same popup. Hosts: `render.idPrefix` sets the prefix of every id and internal link (default `tsr-`) — give a second document on the page its own; one engine now holds a document per container (`handle.dispose()` frees one); the popup, print and the dev audit are behaviours (`createEngine({ behaviors: [...defaultBehaviors(), devAudit()] })`); the popup class is `.tsr-refpop` (was `.tsr-notepop`) and the link colour is `--tsr-link`.
- [P3-04] `#link({target: "label"})[text]` links to a label with your own text (the `#tsr-` spelling is the engine's). A labelled rule or raw block can be referenced (its anchor is kept on the static page too).
