# .tsm author-facing changes

This log lists every change that an author of `.tsm` documents can observe:
new syntax, changed meaning of existing syntax, new diagnostics and changed
defaults. Each entry names the remediation plan step
(`docs/remediation/PLAN.md`) that introduced it and, where needed, how to
migrate an existing document.

Format: `- [step] what changed — migration (if any)`.

## Unreleased (remediation/audit-2026-10)

- [P0-04] A `$` that is not closed within its own block (paragraph, heading, cell, link text) is literal text. It no longer takes a closing `$` from a later block, which used to swallow and duplicate the blocks in between.
- [P0-04] An inline `%--` comment that is not closed within its block is literal text, with an error diagnostic, instead of hiding the rest of the document.
- [P0-04] An unbalanced `#let` or `#{` statement reports `statement-unclosed` and is dropped up to the next blank line or the next block start (heading, list item, quote, fence, region, statement). It no longer swallows the rest of the document (`#let`) or pastes broken JavaScript that failed the whole document (`#{`). A `#{` used to recover at the end of its line.
- [P0-04] CRLF line endings read exactly like LF: fence bodies, comments and multi-line formulas no longer carry `\r`, and lines ending in `\r\n` join paragraphs as LF lines do.
- [P0-04] Inside regions, a `|` within `$…$` or a code span no longer splits table cells: `$|x|$` is one formula.
- [P0-05] A runtime error in a block (a ReferenceError in a splice, a throwing `#{…}`) no longer fails the whole document. The block renders as an error block (`script-error`) and the other blocks render normally. A JavaScript syntax error in a statement or splice is isolated to its block (`script-syntax`).
- [P0-05] `#let list = 1` (or any other constructor name) is legal: it shadows the name for your code, while `- item` lists and other markup keep working. Names starting with `__` are reserved (`reserved-name`).
- [P0-05] Repeating `#let x = …` reassigns `x` (it used to fail the whole document). Closures see the latest value.
- [P0-05] `#if`, `#for`, `#while`, `#use`, `#else` and other JavaScript keywords used as a splice head become error blocks (`keyword-unsupported`, `reserved-word`) until the keyword forms land. Before, they failed the whole document.
- [P0-05] Region and fence arguments must be named (`#!table(cols: 3)`, ```` ```js(lineNo: 1) ````). A positional list such as `#!table(3)` is an error block (`header-positional`) instead of failing the document.
- [P0-05] `#let` and `#{…}` inside a list item, quote or region show an error block (`statement-nested-unsupported`) instead of silently disappearing.
- [P0-05] A throwing `$.region` handler becomes an error block (`region-error`), as a fence handler already did.
- [P0-06] Style values are validated. Accepted values:
  - `color`: `#hex`, a color name, `rgb()`/`hsl()`, or `var(--name)`;
  - `font`: a comma-separated family list;
  - `lang`: a BCP-47 tag;
  - `sizePx`: 1–2000.

  Anything else (for example `"red;letter-spacing:5px"`) is dropped with an `ops-arg` warning, so a value can no longer inject CSS. Other numeric arguments are clamped into their range: heading `level` is 1–6, table `cols` is 1–64.
- [P0-10] A citation's generated text (`[1]`, `??`) is its own run: copying a passage keeps the punctuation and words next to a citation, and the bracket is no longer copied as prose. A line-final hyphen of a linked word stays inside the link.
- [P0-11] `#bibliography(src)` in Node reads only files below the site root or the document's own folder (a `../../..` path is refused with `bib-load`), and the error points at the `#bibliography` call.
- [P0-11] An image declared with only `w` (or only `h`) keeps that dimension; the other follows the image's aspect ratio (the provider used to overwrite `w`).
- [P0-12] Line breaking follows TeX's rules: the space at a break and at a line start no longer counts in the line's width, the last line may shrink like any other, hyphenation points are discretionary breaks. Some paragraphs break differently (usually fewer widows and loose lines). A word, URL or formula wider than the line is set on a line of its own and overflows it (`overfull-line` warning) instead of crushing the whole paragraph onto one line.
- [P1-02] Footnote markers inside bold or italic text keep their emphasis on the no-JS page (`<sup><strong>1</strong></sup>`).
- [P1-03] Host configuration is one settings document (docs/settings-table.md): `createEngine().typeset(src, el, {settings: {doc: {lang: 'en'}, code: {snapKerning: true}}})`, `renderTsm(src, {settings})`, `export-static --settings site.json`, `tsrc --settings/--set/--profile`. The old named options (`widthPx`, `fontFamily`, `lang`, `punctCompress`, …) remain as sugar; unknown paths and bad values are `setting-unknown` / `setting-type` warnings. Release note: the browser's default body font is now the registry default `"Crimson Text", Georgia, serif` (it was `Georgia, serif` in the shell only), and `export-static` takes the document language from `doc.lang` (English documents export with `lang="en"` and English supplements).
- [P1-04] Fonts are measured per face (family, size, weight, italic), and the typeset root carries the measured font roles (`--tsr-font-body/-cjk/-mono/-mono-cjk`), its language and base size, so the page paints exactly what was measured without host CSS. CJK text inside code is measured in the CJK font (`fonts.monoCjk`, else `fonts.cjk`) as browsers paint it; CJK italics are measured upright, as they are painted (with emphasis marks). New setting `fonts.monoCjk`.
- [P1-06] Inline constructs may cross a line break inside their paragraph whatever separates the lines — a quote's `> `, a list item's indentation, trailing blanks or CRLF: `$a +⏎> b$` in a quote is one formula, `#f[…⏎…]` and `[link⏎text](u)` work across lines. Inside formulas and splice code the line break reads as a bare newline (the next line's indentation is not part of it).
- [P1-06] Code spans follow the run-length rule: ``` ``a`b`` ``` is the code `` a`b ``; a run of N backticks closes only at a run of exactly N, and an unclosed run is literal as a whole. One leading and one trailing space are stripped when both are present (`` ` x ` `` is `x`), so ``` `` `tick` `` ``` shows `` `tick` ``.
- [P1-06] Inside a formula `\$` is a literal dollar (`$a \$ b$`); every other backslash sequence reaches the math parser unchanged.
- [P1-06] Brackets inside formulas, code spans, comments and splice arguments no longer close a footnote, a content argument or link text: `` #strong[code `a]b` here] `` ends after the code span, `[range $[0,1)$](u)` is a link, and `\]` works in `^[…]`, `@[…]`, `#f[…]` and link text alike. A `$` inside link text or a content argument that has no closer before the bracket stays literal (`[price $5](u) and $x$`).
- [P1-06] `@[a, b]` lists ids separated by commas; spaces around each id are ignored.
- [P1-07] A tab advances to the next multiple of 4 columns, so tab-indented list continuations, nested lists and quotes work (a tab used to end the list).
- [P1-07] A list item interrupts a paragraph only when it has content, and a numbered item only when its number is 1: `1984. Then …` on the second line of a paragraph continues the paragraph.
- [P1-07] `-`, `+` and `N.` lists never merge: `+ a` followed by `3. b` makes two lists, the second starting at 3 (the start number used to be dropped). An `N.` that breaks the numbering of its list is reported (`list-number`, info).
- [P1-07] A blank line ends a quote (`> a⏎⏎> b` is two quotes).
- [P1-07] Fences and block comments inside a quote or list item end with their container; fence content inside a list item keeps its own indentation (it used to lose the item's indentation twice).
- [P1-07] A `%--` comment line inside a paragraph no longer splits it. Text after `--%`, `}` or `;` on the same line is kept (it was silently dropped): `#{ let z = 3 } and after: #z.`.
- [P1-07] `#let` and `#{…}` may span lines inside lists, quotes and regions as at the top level (they still report `statement-nested-unsupported` until P2-12), and a broken one inside a container is an error block up to the next blank line instead of the rest of its line only.
- [P1-07] A region closer `#name!` closes the innermost open region of that name; regions opened inside it report `region-unclosed`, as does a region whose quote or list item ends. A closer with no open region of its name is an error block (`region-orphan`) instead of a `#name` splice.
- [P1-08] A construct left open at the end of a line — a formula, a code span, a splice's parentheses, a content argument, an inline `%--` comment — continues onto the following lines of its paragraph, and markup at the start of those lines is text: a formula whose second line starts with `- b` no longer turns into a list, a mid-line `%--` hides the `= …` and `- …` lines up to its `--%`. A formula, code span or call that is still open at a blank line (a comment or block body: at the end of its container) is literal text from its opener, and the following lines are read as usual.
- [P1-08] Content arguments and footnotes take block content: `#callout[` on its own line, then lists, blank lines and paragraphs, closed by a `]` line at the opener's indentation. Bodies are read as blocks, so a body starting with a block marker is that block (`#quote[- x]` is a list); a body that is one paragraph stays inline as before. A footnote `^[…]` may hold several paragraphs and lists.
- [P1-09] ```` ```tsm ```` blocks are highlighted by the engine itself (markers, splice heads, code, formulas, references, labels, emphasis, links, cell bars, fence bodies, comments), with the same tokens the VS Code extension now shows; the extension's outline, folding and completion also come from the engine (region-name completion lists `figure`, `table` and the document's own regions; reference completion includes CJK labels).
- [P1-10] Supplement words come from locale packs chosen by the document language: Japanese documents get 図/表/式 and Traditional Chinese (zh-TW, zh-HK, zh-Hant) 圖/表/式 (both used to get 图); every other language keeps the English words. The `terms.*` settings now override single words on top of the document language (they used to be reset by `doc.lang`).
- [P1-10] A reference to a labelled group that is not a figure (an aside) shows the label text, as the `ref-unnumbered` note says (it showed the figure word with no number).
- [P2-01] Splices follow one content rule: a node stays itself, strings and numbers are text, `null`/`undefined`/`false` render nothing (`#x` of `undefined` warns `splice-undefined`), arrays flatten, a function is an error unless it is nullary (`#toc`), other objects show as text with a `splice-object` note.
- [P2-02] Error containment reaches every block: a list item's, quote's or region's paragraph whose code throws becomes an error in its place, and the rest of the list, quote or region renders. A JavaScript syntax error is isolated to the splice or statement that has it, and editing prose no longer re-checks the code. `#let class = 1` (a reserved word) is an error block (`script-syntax`) instead of failing the document. Content arguments go into the call after its own arguments, whatever the argument list looks like: `#f()[c]`, `#f(a,)[c]`, `#f(/* note */)[c]`.
- [P2-02] A splice or statement may `await`: `#let data = await load()`, `#(await f())`.
- [P2-02] Diagnostics of running code point at what runs: `splice-undefined` at the splice, `region-error` at the region (it pointed at the statement that registered the handler).
- [P2-03] Every kind has a constructor, and all constructors share one calling convention: leading arguments bind to the constructor's parameters while they fit (`heading(level, label)`, `list(ordered, start)`, `codeblock(lang, lines)`, `image(src)`, `link(url)`, `raw(html)`, …), then one options object, then the content. `#heading(2)[Title]` and `#list(false)[…]` now bind their content as content (it used to become the label or the start number). New: `group`, `table`, `row`, `cell`, `raw`, `collect`, `styled`, `figure`, `node(kind, attrs, …kids)`. An unknown option is dropped with a `ctor-arg` warning; `width`/`height` mean `w`/`h`, `float` means `side`.
- [P2-03] `$.ctor(name, next => (call, ctx) => content)` overrides a constructor everywhere — explicit calls and markup alike (`$.ctor("strong", …)` changes `*x*` too) — and `next` is the constructor it replaced. A throwing override is an error in place (`ctor-error`).
- [P2-03] `$.region(name, (body, ctx) => content)`: a region handler now receives a Body — `body.blocks()` (the interior as blocks), `body.rows()` (the table reading) — and `ctx` (`ctx.args` are the header's options, `ctx.next(body)` delegates to the previous handler or the default region). It returns the constructor, so `#let callout = $.region("callout", …)` also makes `#callout({…})[…]` work — the same as the region. Migration: a handler `(args, children) => …` becomes `(body, ctx) => …` with `ctx.args` and `body.blocks()`. `$.fence` handlers gain `ctx.next(body)`.
- [P2-05] Every constructor accepts `label`, `role`, `slot`, `syn`, `copy`, `class` and `ext: {name: value}` (scalar data for scripts and hosts), and `style: {…}` wraps the result in a style scope: `#quote({label: "q1", role: "lead"}, para("…"))`, `#em({style: {color: "#a8432a"}}, "word")`. A label works on any block, so `@q1` reaches a labelled quote, list or code block.
- [P2-05] `field(name)` is a placeholder for a value an element supplies; until elements arrive (P2-07) it reads `??` with a `field-unresolved` warning.
- [P2-05] `$.declare(type, name, data, ...templates)` records a declaration (element, counter, collector, rule, …) for the steps that read them; declaring a name of the same type twice keeps the later one (`decl-redeclared`).
- [P2-06] A splice call's arguments may be named — `#card(tone: "warm", label: "c1")[…]` passes one options object `{tone, label}` (it was a JavaScript syntax error). Named and positional arguments together are an error (`mixed-args`) that says how to name them all.
- [P2-06] Region headers and fence arguments must be a named list: a shorthand-only or spread-only header (`#!table(cols)`, `#!x(...opts)`) is now an error (`header-positional`) like a positional one; the message gives the fix (`#!table(cols: cols)`).
- [P2-06] A fence's info line reads like Markdown: ```` ```js(lineNo: true) a title <code1> ```` is the tag `js`, its arguments, free info words (for fence handlers: `ctx.info`) and a label. Before, everything up to `(` was the language.
- [P2-06] ` <id>` labels a region (`#!box(tone: "warm") <b1>`), a fence and any display formula, as it labels a heading; an explicit `label:` argument wins (`label-conflict`). On an inline formula the label is dropped (`label-orphan`) until inline anchors exist. A paragraph ending in ` <x>` stays text and gets the `label-like-text` note (`\<` silences it).
- [P2-06] Labels written as ` <id>` take any character but whitespace and `<>[]@,;\`: `<标签>` and `<sec:intro>` work; `<a]b>` is no longer a label (set such names with `label:` and reference them as `@[a\]b]`).
- [P2-06] Bare references join with `-`, `.` and `:` — `@sec:intro` refers to `sec:intro`, and a period after a reference stays prose (`see @fig-1.`). `@fig[p. 5]` is parsed as a reference with a supplement; it renders as before until P2-09 gives supplements their meaning.
- [P2-07] Documents declare their own elements, counters and collectors, with the same power as the built-ins: `$.element('theorem', {counter: {name: 'thm', within: 'heading', depth: 1}, supplement: {en: 'Theorem '}, title: {arg: 'title'}, sites: [{where: 'prepend:first-para', template: [strong(slot('supplement'), slot('number')), ' ']}]})` makes `#!theorem(label: "t1", title: "…") … #theorem!` numbered "Theorem 2.1" and `@t1` read "Theorem 2.1" (a labelled `#!theorem` region used to render `??` for its references); `$.element('lemma', {like: 'theorem', …})` shares the counter. Declarations are hoisted: they apply to the whole document wherever they are written. `$.element('heading', {…})` patches the built-in row field by field. Also `$.counter(name, {within, numbering, start, gap, levels})`, `$.counter.system(name, {symbols, mode})`, `$.collector(name, {…})`; `$.labels.import` is a placeholder until P3-31.
- [P2-07] Numbering patterns: `1`, `a`, `A`, `i`, `I`, `①`, `一`, `*` and `{system}` with any prefix, separators and suffix (`'A.1'`, `'(i)'`, `'§1'`).
- [P2-07] `counterUpdate(name, {set, step, add, numbering, supplement})` (also `$.counter.update`) is a counter change placed where it is spliced: `#let appendix = () => counterUpdate('heading', {set: [0], numbering: 'A.1', supplement: {term: 'appendix'}})` then `#appendix()` letters the following chapters, their equations and their references ("Appendix A", "(A.1)"). A line holding only events vanishes. A `counterUpdate` whose value is discarded (`#{ counterUpdate(…) }`) does nothing and says so (`event-unplaced`).
- [P2-07] `ref(target, {form, supplement})`: `form: 'number' | 'title' | 'supplement' | 'full'` or a form the element declares; `supplement` replaces the word (`#ref("t1", {supplement: "Thm. "})` → "Thm. 2.1"). `field(name)` now reads the enclosing element's value (number, supplement, title, label).
- [P2-07] A region's options other than `label` and the style keys are kept as the instance's data (`#!aside(title: "pipes")` carries `title`; they were dropped); an element row can read them (`title: {arg: 'title'}`).
- [P2-07] `#bibliography(…)` stands where it is written (it was always moved to the end of the document), and `cited: 'cited-then-all'` lists every entry after the cited ones (`all: true` still works). Two bibliographies list the same entries, each in its place.
- [P2-07] The host may patch the built-in rows: `{"semantics": {"elements": {"figure": {"supplement": {"text": "Fig. "}}}, "counters": {"heading": {"gap": "one"}}}}`.
- [P2-07] Japanese, Chinese and English packs gain the `appendix` word (付録, 附录/附錄, Appendix).
- [P2-08] A region's style goes in `style: {…}`: `#!aside(style: {font: '"LXGW WenKai", serif', lang: "zh-TW"}) … #aside!`. The header keys `font`, `lang`, `color`, `sizePx` at the top level no longer style the region (they become the region's data) and say so (`ctor-arg` warning with the fix). The style applies to the region itself instead of a wrapper around it.
- [P2-08] Style patches gain `weight` (100–900), `fontRole` (`body` | `mono`), `baseline` (`super` | `sub`), `decoration` (`['under', 'over', 'strike']`), `size` (`'0.7em'`, `'70%'` multiply; `'22px'` sets the size) and `code: {hang: 'content'}` (a code run's continuation lines hang at its content, as comments do); `bold: false` sets weight 400. `sizePx` now replaces the inherited size outright, as CSS does. An unknown style key is reported (`ctor-arg`).
- [P2-08] `{style: {…}}` on any constructor styles that node itself (it used to wrap it in a separate styled node).
- [P2-08] A code run is no longer recognised as a comment by its colour: authored code lines that relied on `style({color: "var(--tsr-tok-comment)"}, …)` for comment-aware wrapping add `code: {hang: "content"}`.
- [P2-08] Op buffers older than version 11 are no longer read (the one format break of the remediation): re-execute documents rather than replaying stored buffers.
- [P2-09] The bracket after a reference means something now (D-L01): `@fig-a[Fig.]` reads "Fig. 1" (it replaces the word), and after a citation it is the locator: `@kp81[p. 5]` reads "[1, p. 5]". It used to print as literal text after the reference ("Figure 1[Fig.]").
- [P2-09] `@[a, b]` of labels reads each reference in turn ("Figure 1, Figure 2"; it used to be unresolved); of citation keys, three or more consecutive numbers compress ("[1–3]").
- [P2-10] A line break inside a paragraph is a soft break carried to the engine, which joins the lines with a space, or seamlessly between two CJK characters (as before) — now also when the next line is indented or the line ends in blanks (an indented continuation used to put a space between two CJK characters).
- [P2-11] A region's text is kept as written: `|` inside a figure caption or an aside stays as typed (it used to become " | "), and its line joins are soft breaks like anywhere else (CJK lines join seamlessly inside regions too). A table cell is cut only by a `|` at the top level of the line: `*a | b*`, `` `x | y` ``, `$|x|$` and a splice's arguments stay one cell, `\|` is a literal bar; markup that crosses a line of a table row stays in the row it starts (`row-spans-markup`).
- [P2-11] A display formula inside a region (an aside, a theorem) is a numbered block with its label, as at the top level (it used to be set inline and lose its label). A labelled display formula in the middle of a paragraph is set inline and says its label is dropped (`label-dropped`).
- [P2-11] A block constructor inside a paragraph (`See #toc() here.`) warns `block-in-inline` (once; it used to warn `shape-unsupported`). Text placed directly in a block-level group becomes a paragraph (it used to disappear). Images and raw boxes may stand in text or on their own.
- [P2-12] `#if (c) [A] else if (d) [B] else [C]`, `#for (const x of xs) [B]` and `#while (c) [B]` work, inline or at a line start with bodies over several lines (they used to be `keyword-unsupported` errors). A loop's iterations join (`#for (…) [- #x]` is one list); a body's `#let` names are its own (`#let n = n + 1` inside reads the outer `n` and leaves it unchanged); an error in one iteration stays in that iteration. A one-line body keeps its edge spaces: `[#x, ]` separates the items.
- [P2-12] `#let` and `#{…}` lines work inside list items, quotes, regions and content bodies (they used to be `statement-nested-unsupported` errors). `#let x = …` there binds `x` for the whole document (or the keyword body around it); a nested `#{ let y = … }` keeps `y` to itself (info `statement-local`); a style pushed by a nested statement ends with it (`style-in-value`, until `$.set` in P3-01).
- [P2-12] **Behavior change:** `#let x = [ … ]` is a content literal — its body is markup, and `#x` places it (any number of times). It used to be a JavaScript array: write `#let xs = Array.of(1, 2, 3)` or `#{ let xs = [1, 2, 3] }` instead.
- [P2-13] `` m`…` `` parses markup: `` m`*bold* ${x}` `` is bold text followed by the value of `x` (it used to be the literal characters). The template's raw strings are read, so a backslash is a markup escape. `m.parse(src, {scope})` parses a string, looking up `#name` and `#a.b` on `scope` (then the standard library); a fence handler gets the same as `ctx.m` (`ctx.m.parse(body, {offset: ctx.offset})` keeps exact source positions). Fragments run no JavaScript: `#f(x)`, statements and keyword forms inside them stay text (info `fragment-splice`); their parse errors are reported where they were parsed (`fragment-parse`).
- [P2-13] Sidecar notes in a code block (`` ```js(sidecar: "///") ``) are full markup with exact source positions — a `^[…]` in a note is a real footnote, references and math work as before — and they appear on the semantic page after the code. In a document with CRLF line endings or an indented fence, a fence handler's `ctx.lineOffsets` now gives each line's true offset.
